# 테스트

라즈베리파이나 아두이노 없이 개발 PC에서 전부 돕니다. Qt 는 화면 없이(offscreen)
띄우고, 시리얼 포트는 아두이노로 나간 바이트를 기록하는 가짜 포트로 대신합니다.

```bash
python3 tests/run_all.py            # 전체
python3 tests/run_all.py leds       # 이름에 leds 가 들어간 것만
python3 tests/render_screens.py     # 모든 화면을 PNG 로 저장
```

각 테스트는 별도 프로세스에서 돕니다. `QApplication` 과 `main` 모듈 전역 상태를
공유하면 서로 간섭하기 때문입니다.

## 무엇을 지키고 있나

| 파일 | 지키는 것 |
|---|---|
| `../test_sorter.py` | 조합 선택 규칙, 거절 순환, 원자적 설정 저장. **PyQt5 없이** 돌아야 하며 OTA 검증 관문으로도 쓰입니다 |
| `test_layout.py` | 800x480 안에 다 들어가는지, 오버레이가 스스로 닫히는지 |
| `test_leds.py` | 조합 LED 송신 8가지 경로. 중복 억제가 필요한 신호를 삼키지 않는지 |
| `test_operation.py` | 재조합, 생산 실적 기록, 부족분 표시, 프리셋 저장, 설정 백업 |
| `test_startup.py` | 시작 준비 절차, 잘못된 영점 감지, 아두이노 재시작 감지, 보정 흐름 |
| `test_assembly.py` | 허브보드 1장(저울 1,2,7,8) 상태, 그리고 12채널로 넘어갈 때 |
| `test_ota_rollback.sh` | 깨진 코드를 푸시해도 현장 기기가 이전 커밋으로 되돌아가는지 |

## 조합 로직을 고칠 때

`../test_sorter.py` 를 반드시 함께 갱신하세요. OTA 가 `git pull` 직후 이 파일을
실행해서, 실패하면 pull 직전 커밋으로 되돌립니다. 이 파일이 현장 기기가
크래시 루프에 빠지지 않게 막는 유일한 장치입니다.

PyQt5 를 import 하면 라즈베리파이에서 관문이 무거워지므로 `test_sorter.py` 에는
Qt 의존성을 넣지 마세요. 화면이 필요한 검증은 `tests/` 쪽에 넣습니다.

## 실기에서만 확인되는 것

소프트웨어로는 알 수 없어 사람이 봐야 하는 항목입니다.

- **배선과 화면 번호가 맞는지.** 저울점검에서 채널별 `LED 확인` 을 눌러 실물 위치와
  대조하세요. 뒤바뀌어 있으면 조합 LED 가 엉뚱한 저울에 켜지는데 코드로는
  구분할 방법이 없습니다
- 시작 준비 절차의 LED 순차 훑기(1→12)가 실제로 순서대로 켜지는지
- 로드셀 보정값이 실제 분동(430g)과 맞는지

## 화면 이미지

`render_screens.py` 결과는 `tests/_screens/` 에 쌓이며 git 에 올라가지 않습니다.
판정에는 쓰지 않고, 라즈베리파이 없이 화면 변경을 눈으로 검토할 때만 씁니다.
